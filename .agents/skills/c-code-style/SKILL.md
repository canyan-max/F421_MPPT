# C 代码规范

## 格式来源
- 每次应用前读取当前工作区根目录的 `.clang-format`，以实际配置为准，不复制一份配置到 skill 中。
- 新建文件的文件头、分区和保护宏同时遵循项目 `c-header-template` skill。该 skill 管文件布局，本 skill 管代码规范，.clang-format 管排版；用户明确要求的文件头布局优先于 formatter 默认行为。

## 变量命名
- 普通全局变量使用 `g_` 前缀，包括文件作用域的 static 变量，例如 `g_adc_count`、`g_adc_running`。`g_` 是命名约定，不改变变量的作用域或链接属性；普通局部变量不加 `g_`。
- 数据指针变量使用 `p_` 前缀，例如 `p_adc_buffer`。
- 函数指针变量使用 `pf_` 前缀，即使类型通过 typedef 隐藏了指针形式，例如 `plat_adc_callback_t pf_adc_callback`。
- 前缀按函数指针 `pf_`、数据指针 `p_`、普通全局变量 `g_` 的顺序选择，不叠加成 `g_p_` 或 `g_pf_`。const、volatile 不改变前缀选择。
- 用户确认的声明示例：

```c
static volatile uint16_t *p_adc_buffer;
static uint16_t g_adc_count;
static plat_adc_callback_t pf_adc_callback;
static volatile uint8_t g_adc_running;
```

- 其他命名要求暂沿用模块已有风格。新增或修改变量时遵循上述规则；既有变量仅在任务涉及或用户要求时重命名，并同步所有引用，不改变类型、作用域或逻辑。

## 指针形参
- 数据指针形参名使用 `p_` 前缀，例如 `p_data`、`p_buffer`；函数指针形参沿用 `pf_` 前缀。
- 函数只读取指向的数据时，将 const 放在所指类型前，例如 `const uint8_t *p_data`。指针星号靠近参数名，遵循 `.clang-format`。
- 需要通过指针写入数据的输出或输入输出参数使用可写类型，例如 `uint8_t *p_buffer`，不为统一外观强加 const。
- 区分所指数据只读与指针本身不可修改：`const uint8_t *p_data` 约束所指数据；`uint8_t *const p_data` 约束局部指针，不可互相替代。仅在确有需要时使用指针本身的 const。
- 调整已有接口 const 时核对声明、定义和调用方兼容性，不通过强制转换移除 const。const 不表示底层数据不会变化；DMA 或硬件共享数据按实际契约保留 volatile，不能因添加 const 而移除 volatile，也不能将 volatile 当成原子性或同步保证。

```c
static uint16_t get_u16_be(const uint8_t *p_data)
```
## 函数入口校验
- 函数入口先检查指针及数组参数合法性，通过后再解引用、索引或调用回调；指针判断采用 `NULL == p_data`。
- 数组参数同时核对长度、容量、索引范围及接口要求的最小数据量；指针非空不代表数组长度足够。C 中数组形参会退化为指针，不能用 sizeof 形参推算元素数量。
- 接口传入长度时先检查长度满足本次访问范围；缺少长度时依据明确的固定长度契约处理，不凭指针判断缓冲区大小。新增接口按需显式传入长度，已有接口变更须同步调用方。
- 对允许为空的可选指针、允许零长度的接口按明确契约处理，不机械拒绝合法调用。指针判空和长度校验只能验证已知条件，不能证明任意地址可访问或调用方提供的容量真实。
- 参数失败时提前返回，错误码、默认值或错误上报沿用接口约定；不保留 `return xx` 占位符，不擅自选择会与有效数据混淆的错误返回值。
- 例如 get_u16_be 读取两个字节时，除空指针检查外还必须由长度参数或明确的调用契约保证至少两个可读字节。
- 检查使用 Allman 大括号和四空格缩进，禁止为了简短把 if、return、括号合并成一行。
## 条件比较
- 相等、不等比较的一侧为常量时，将常量写在左侧，例如 `NULL == p_buffer`、`NULL != pf_callback`、`0U == count`、`0U != g_adc_running`。
- 保留常量的类型后缀及原有表达式含义；运算符两侧空格及长条件换行由 `.clang-format` 处理，不照抄示例中缺失或多余的空格。
- 调整比较方向时保留所有校验条件，不因缩短示例而删除 callback 空指针、通道数量或指针对齐检查。

```c
if(NULL == p_buffer || NULL == pf_callback || 0U == count ||
   0U != count % (2U * PLAT_ADC_CHANNEL_COUNT) ||
   0U != ((uint32_t)p_buffer & 1U))
{
    /* Existing error handling. */
}
```
## 数值常量
- 表示无符号整数的数值常量带 `U` 后缀，比较、数组索引和函数实参中均适用，例如 `0U`、`p_adu[1U]`、`append_crc(p_adu, 6U)`。
- 变量名和宏名本身不加类型后缀；常量宏在定义的数值上加后缀，例如 `#define MODBUS_RTU_FC_READ_HOLDING_REGISTERS (0x03U)`。
- `U` 表示 unsigned int，不表示 uint8_t；不为了匹配形参或数组元素类型机械添加强制转换。窄化赋值前按实际需要检查范围。
- 有符号值、负数、浮点值及更宽整数使用符合实际类型的写法，不把所有数值机械改成无符号。
## 宏定义
- 宏名统一采用大写字母、数字和下划线（UPPER_SNAKE_CASE），例如 `XXXX_AAA`、`BSP_UART_RX_BUF_SIZE`；数字不作为首字符。
- 数值常量宏和普通表达式宏的替换值必须用括号包住，保留适当的类型后缀，例如 `(2048U)`。字符串、include 路径、属性修饰和 token 拼接等特殊用途先保持语法与使用契约，不机械加括号导致字符串拼接等行为失效。
- 有用途或限制说明时放在行尾注释中；按实际含义填写，不复制无关说明。

```c
#define BSP_UART_RX_BUF_SIZE  (2048U)  /* power of 2 required (kfifo mask) */
```

- 头文件保护宏等没有替换值的宏只保留宏名，不加括号。
- 函数式宏不机械套用常量格式；表达式宏的参与运算参数及整体表达式加括号，注意参数重复求值，不把带副作用的表达式传给会重复求值的宏。已有宏整理必须保留语义。
- 当前 `.clang-format` 设置 `SkipMacroDefinitionBody: true`，编写时主动保证常量括号正确，不依赖格式化工具自动补齐。
## 枚举类型
- 使用带标签的 typedef enum；标签采用大写下划线并以 `_T` 结尾，typedef 类型名采用小写下划线并以 `_t` 结尾。
- 枚举成员采用大写下划线，并带所属模块或类型前缀。
- 首个成员必须显式指定起始值，例如 `= 0U`；实际起始值以业务或协议要求为准，不一律改成零。
- 连续成员可以自动递增；非连续值、协议或硬件规定的值显式指定，不因统一格式改变既有数值。
- 示例中的末尾 `_NUM` 表示数量，保留末项逗号。只有从零开始的连续枚举才可直接将 `_NUM` 用作数量；特殊取值枚举不机械添加数量项。

```c
typedef enum PLAT_DCMI_EVENT_T
{
    PLAT_DCMI_EVENT_FRAME_READY = 0U,
    PLAT_DCMI_EVENT_OVERRUN,
    PLAT_DCMI_EVENT_ERROR,
    PLAT_DCMI_EVENT_NUM,
} plat_dcmi_event_t;
```
## 重点要求
- 代码以 80 列为换行目标（`ColumnLimit: 80`）；长条件、参数列表等按 formatter 规则换行，不通过压缩空格或改写逻辑凑列宽。
- if、else、for、while、do 的语句体必须加大括号，即使只有一条语句；else if 链保留常规结构。大括号使用 Allman 格式独占一行，禁止把条件和执行语句合在一行。
- 当前 formatter 配置不保证自动补齐大括号，编写或修改时主动补齐；添加时保持原有 else 归属和控制流程，不顺带修改无关代码。
- 其余缩进、空格、对齐、指针及换行行为交给 `.clang-format`。当前为四空格、禁用 tab、`if(condition)`，不手工另立冲突规则。
- 80 列是格式化目标，不保证所有行硬截断；不可拆分的字符串、标识符及模板分隔注释不得为凑列宽而破坏内容。

## 初始化、边界及状态处理
- 全局变量及文件作用域 static 变量需要零值或空指针初值时可以省略显式初始化，使用 C 的静态存储期默认初始化；需要非零初值时显式指定。此规则不适用于自动存储期局部变量，也不覆盖 no-init 等特殊链接段的启动约定。
- 局部变量使用前必须初始化或在所有可达路径上明确赋值。指针可初始化为 NULL，其他变量按实际含义选择初始值，不用随意默认值掩盖遗漏分支。
- 真实数组的元素数量优先使用 sizeof(array) / sizeof(array[0U]) 推导，避免手写数量与数组定义失配；此方法禁止用于指针或已退化为指针的函数数组形参。
- 状态返回值必须检查并按接口约定处理；例如 ADC 启动失败时不继续执行依赖有效采样的操作。确实允许忽略时说明原因，不用强转 void 代替错误处理。

## 注释和物理量单位
- 注释解释原因、单位和限制，不仅复述代码动作。
- 物理量变量名明确单位，例如 battery_voltage_mv、charge_current_ma；单位后缀与变量的其他命名前缀同时适用。
- 区分 ADC 原始值、换算后的物理量和定时器计数值，名称或接口注释注明其含义，避免直接混用。
## Include 顺序
- 依次包含 C 标准库头文件、厂商及厂商生成头文件、项目自有头文件，各组之间不插入空行。项目自有组内优先包含对应接口或同名头文件。
- 根据头文件实际归属分组，不单凭尖括号或双引号推断。当前 SortIncludes: Never，主动维护顺序，不依赖 formatter 自动排序。
- 保留组内确有依赖的顺序；调整后编译确认，不增加无用 include。

## 应用范围与检查
- 仅格式化本次授权修改的自研文件或相关范围；不顺带重排全工程、厂商库、第三方或生成代码。
- 文件头按 c-header-template 保留，包含 @brief 续行对齐；对文件头以后的代码范围运行格式化并检查差异。不要用全文格式化或全文 dry-run 的通过与否覆盖已确认的文件头例外。
- 使用可用的 clang-format 并显式指定工作区配置（如 `--style=file`）；先检查工具版本是否支持当前配置。工具缺失或配置不兼容时说明，不擅自降级或删除配置项。
- clang-format 只验证排版，不能证明命名、边界检查、错误处理或硬件正确；这些规则需另行检查。检查格式化差异，保留 include 顺序、宏和注释含义，确认没有逻辑变化。
- 实际源码修改按项目 AGENTS.md 执行编译验证；仅修改 skill 文档无需编译。
